# Examples

Each program here demonstrates one part of the library on a problem small
enough to run on a laptop, and most check themselves against an exact
solution, a closed form or a second formulation. This page explains how to
run them and look at the results, and then what each one does.

## Running them

The examples are built with the library when configured with `-DBUILD_EXAMPLES=ON` (off by default)
and are run from the build tree, never from this source directory:

```
cd <build>/examples
./love_numbers                         # serial build
mpiexec -np 4 ./love_numbers           # parallel build
./love_numbers -h                      # the options of any example
```

Every example is one source for both builds: a parallel program when MFEM was
built with MPI, a serial one otherwise. Use the `mpiexec` of the MPI that MFEM
was built with (with PETSc's MPICH, `<petsc>/bin/mpiexec`). The meshes are read
from `../data`, which the build fills: the small MFEM meshes are copied from
`data/` and the gmsh meshes are generated by the scripts in `meshes/` (see
`meshes/README.md`).

Everything an example writes (CSV tables, figures, native `.mesh`/`.gf`
files, ParaView collections) goes into the directory it runs in, so into
the build tree.

## Seeing the results

### Fields: GLVis

Fields are sent to [GLVis](https://glvis.org). Start the server in a
terminal of its own, and leave it running:

```
glvis
```

Then run an example. A window opens for each field it shows, and the
time-dependent examples animate. `-vis` is on by default in most examples
(`-no-vis` turns it off). Without a server they carry on without it.
In parallel each rank sends its piece and GLVis puts the pieces together.

A few GLVis keys go a long way: `j` toggles perspective, `l` lighting, `c`
the colour bar, `m` the mesh lines, `i` cuts a 3-D body open, `R` steps
through preset viewpoints, `F11`/`F12` shrink and grow the elements, `q`
closes the window. `h` in a window prints the full list. The examples set
a first view with these keys (`Rjlbc` in 2-D, `RRRilc` in 3-D).

### Curves: CSV tables and plot_csv.py

Results that are curves rather than fields (Love numbers by degree, time
histories, convergence) are written as CSV tables, named after the example
(`-csv <file>` renames, `-csv ""` turns it off). The build puts a plotting
script beside the programs:

```
python3 plot_csv.py viscoelastic_love_numbers.csv          # writes viscoelastic_love_numbers.png
python3 plot_csv.py viscoelastic_love_numbers.csv --show   # and opens a window
python3 plot_csv.py lateral_viscosity.csv --out lv.pdf     # any format matplotlib writes
```

It needs numpy and matplotlib (`pip install numpy matplotlib`). A table
describes its own plot in `# key: value` lines above its header (title,
which columns, panels, log axes); a column called `<name>_exact` is drawn
dashed beside `<name>`. `python3 plot_csv.py -h` lists the keys, which
makes the script usable for tables of your own.

### ParaView

Some examples can also write ParaView collections (`-pv`), into
`ParaView/` under the working directory.

## The examples

The sample runs below are the serial form; put `mpiexec -np N` in front in
a parallel build. Each source file starts with a longer description.

### Potential theory and submeshes

**`poisson_dtn`**: the Poisson equation on the whole space, with the
domain truncated by a homogeneous Neumann condition, the exact
Dirichlet-to-Neumann operator or a multipole expansion, for a uniform
sphere and for a rigidly translated one (the linearised problem), against
the exact solution. Shows: the potential (always sent to GLVis; there is
no `-vis` option). `./poisson_dtn -o 2`

**`transformed_diffusion`**: the Laplace equation on a twisted domain solved
on the undeformed reference mesh with `TransformedDiffusionIntegrator`
(the pull-back approach of the referential problems). Shows: the solution
on the reference mesh, the pulled-back one, and that one pushed forward
(always sent to GLVis; there is no `-vis` option).

**`submesh_injection`**: a tour of `SubMeshDofInjection`: moving fields
between a mesh and a submesh and assembling coupling blocks, serially by
re-indexing and in parallel by hypre products. Shows (`-vis`): the two
fields of the coupled toy problem. `./submesh_injection -o 2 -vis`

**`coupled_poisson`**: two Poisson equations, one on a submesh, coupled
and solved as one block system. Shows (`-vis`): both solutions.

### Self-gravitating elasticity

**`elastogravity_layered`**: `LinearQuasiStaticMixedSelfGravitatingProblem`
under a surface load or a tidal potential: a uniform solid of any shape,
a fluid core under a mantle, or a solid inner core in a fluid outer core;
Schur-CG and block-MINRES solvers compared, rigid-mode diagnostics. Shows
(`-vis`): displacement and potential. `./elastogravity_layered -o 2 -vis`,
`./elastogravity_layered -m ../data/elastogravity_three_layer_3d.msh -o 1 -vis`

**`referential_elastogravity`**: the general referential formulation
beside the Eulerian one on the same problem: two formalisms, one answer,
compared field by field. Shows: both displacements and the referential
potential perturbation.

**`self_gravitating_solvers`**: one problem (a fluid core under a mantle,
degree-2 load), the main linear-solver architectures of the library, with a
table of cost and agreement (the KKT enforcement of the slipping interface
is exercised by `slipping_interface -enforce kkt`). Shows: the solution, and the difference field
of the architecture that agrees least (rigid modes removed). Add `-no-slip`
for a quicker run without the slipping-interface solvers.

**`love_numbers`**: load and tidal Love numbers of a homogeneous
self-gravitating disc or sphere by degree, one solve each; in 3-D beside
the incompressible sphere's closed form. Shows: the load response at one
degree (`-vl`); the CSV plots the Love numbers against degree.
`./love_numbers`, `./love_numbers -m ../data/coupled_poisson.msh -o 2 -lmax 4 -kappa 100`

**`anisotropic_elasticity`**: radially anisotropic (transversely
isotropic, as in PREM) elasticity with `ElasticTensorIntegrator`; with
`-iso`, against `mfem::ElasticityIntegrator`. Shows: the displacement.

**`quasi_static_elasticity`**: the `AssembleForce` / `AddForce` / `Solve`
protocol of the quasi-static problem classes over a sequence of times.
Shows: the displacement.

### Fluids and interfaces

**`gauged_fluid_cavity`**: an elastic body with a fluid core under a
surface pressure, no gravity: the gauged fluid (`SetGaugedFluid`) and its
Tikhonov refinement. Shows: the displacement, and the fluid pressure,
which must be uniform (the fluid displacement itself is gauge).

**`sliding_fluid_ellipse`**: a fluid core that slips along its boundary
inside an elliptical shell, where the interface is not a level surface and
the slip generally cannot be removed by relabelling; a demonstration without
gravity or pre-stress. Shows: the solid and fluid displacements and the
fluid pressure. Compare `-e 0`.

**`slipping_interface`**: a self-gravitating body whose fluid core slips
along the core boundary (`LinearQuasiStaticReferentialSelfGravitatingSlipProblem`)
under a surface load of one degree, with every option of the class: the
single-valued or broken potential (`-zeta`), penalty and augmented
Lagrangian or a KKT multiplier (`-enforce`), the penalty, the sweeps, the
gauge. The default mesh is an aspherical reference body: the mesh has a
different shape, and the exact inverse stretch maps it onto the
spherical physical body, so every result must be that of the spherical
model. Prints the constraint history, the slip null-pair residuals and the
load Love numbers h′, l′, k′ read off the physical surface, with the
response at other degrees ("spurious"), which shows any departure from
spherical symmetry. With `-compare`, the welded gauged referential problem
on the same mesh and Dahlen's problem on the spherical counterpart are
solved too and tabulated beside it. Shows (on the physical body): the
mantle and core displacements, the core pressure, the tangential slip
and the potential; the CSV plots the constraint history.
`./slipping_interface -compare`,
`./slipping_interface -m ../data/spherical_fluid_core_buffer_2d.mesh -zeta single -enforce kkt`,
`./slipping_interface -m ../data/aspherical_fluid_core_buffer_3d.mesh -o 1`

### Pre-stress

**`equilibrium_stress`**: the minimum-norm and minimum-deviatoric
equilibrium-stress generators on a homogeneous ellipse, which admits no
hydrostatic equilibrium. Shows: the minimum-deviatoric pressure, and
|dev T| of both. Compare
`-e 0`.

**`prestress_loading`**: does the deviatoric part of the pre-stress matter
for loading? Full against quasi-hydrostatic pre-stress on ellipses of
growing ellipticity. Shows: |dev S_e| and the response difference on the
physical ellipse; the CSV plots the relative differences against e.
`./prestress_loading`, `./prestress_loading -e 0.3`

### Viscoelasticity

**`viscoelasticity`**: `ViscoelasticOperator` on a quasi-static problem:
Maxwell, standard linear solid, transversely isotropic and power-law
rheologies, every time integrator. Shows: the final displacement.
`./viscoelasticity -m ../data/beam-quad.mesh -p 1 -o 2 -r 1`

**`viscoelastic_schemes`**: cost and accuracy of every time integrator on
a clamped viscoelastic beam, linear or power-law, stiff or not. The CSV
plots the error against the number of solves for each scheme: lower left
is better, the slope is the order. `./viscoelastic_schemes`,
`./viscoelastic_schemes -tau-ratio 100` (a stiff body)

**`viscoelastic_column`**: why material interfaces belong on element
faces. A two-layer Maxwell column with an exact solution, run with the
interface on an element face (exact up to the time stepping) and through
the middle of an element (an error that shrinks only with the element
size, invisible at t = 0+). Shows: the two error fields on one colour
scale; the CSV plots the histories and their errors.
`./viscoelastic_column`, `./viscoelastic_column -nz 16`

**`viscoelastic_loading`**: a load pressed onto a layered Maxwell box with
a weak channel and then removed, without gravity: steady subsidence while
loaded, an elastic spring-back when unloaded, most of the subsidence
permanent. Shows: an animation of u_z on a fixed colour scale; the CSV
plots u_z under the load. `./viscoelastic_loading`,
`./viscoelastic_loading -d 3 -nx 12 -ny 4 -o 1 -n 10`

**`viscoelastic_love_numbers`**: load Love numbers h′(t), k′(t) of a
homogeneous self-gravitating Maxwell sphere under a Heaviside load, against
the closed form from the correspondence principle (one exponential per
degree). Shows: animations of the displacement and the potential; the CSV
plots the histories with the closed form dashed. About a minute on 8
ranks. Try `-kappa 100` (compressibility shows) and `-o 2` (the relaxed
state is badly resolved on this mesh).

**`self_gravitating_relaxation`**: viscoelastic relaxation of a layered
self-gravitating model (Maxwell mantle, fluid core, optional elastic inner
core) under a Heaviside surface load. Shows: an animation of the mantle
displacement; the CSV plots the polar displacement and the norms.
`./self_gravitating_relaxation -o 2 -n 20 -tf 5`

**`lateral_viscosity`**: a self-gravitating disc relaxing a hundred times
faster on its east side than its west, under a load symmetric between the
two. The east and west surface points start and end together (elastic and
relaxed states are symmetric) and part company in between. Shows: log10
of the relaxation time and an animation of u_r; the CSV plots the east,
west and north displacements against log time. `./lateral_viscosity`,
`./lateral_viscosity -tauf 1 -taus 1` (uniform: the symmetric control)

## Writing an example

Copy the nearest one. The conventions they share:

- **one source, both builds**: type aliases (`MeshType`, `SpaceType`,
  `FieldType`, ...) and `#ifdef MFEM_USE_MPI` only where serial and
  parallel genuinely differ, with a comment saying what differs; copies of
  fields that will be normed must be the build's `FieldType`, and printing
  is done on the root rank after collective calls on every rank;
- **output**: fields to GLVis through `examples::GLVisWindow`, curves to
  CSV through `examples::CsvTable` (both in `visualisation.hpp`), with the
  options `-vis`/`-no-vis` and `-csv`, and everything written into the
  working directory;
- **a header** saying what the example shows, what it checks against, what
  it outputs, and a few sample runs;
- a line in `CMakeLists.txt` and an entry on this page.
